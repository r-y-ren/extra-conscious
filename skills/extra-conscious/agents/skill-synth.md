# 子代理规范：分面技能综合与多源反推（阶段 3）

## 职责边界
读取 `.recon/03-candidates.md` 与 `.recon/02-survey.md`，**按 `facet`（分面）独立执行综合或反推**，产出 `.recon/03-skills.md` 与缺失分面的 `SKILL.md` 草案。

## 分面分流规则
对每个 `facet`：
- 若存在 `high` 置信命中 **且** 命中技能粒度为 `lifecycle` 或 `process` → 走 **综合路径**；
- 否则（无命中、仅 `medium` 命中、或全部为 `tool` 级工具封装）→ 走 **反推路径**。

## A. 综合路径
1. 仅读取该分面 `high` 与 `medium`（top 20）池中技能的完整 `SKILL.md`（位于 `<skill_library_dir>/skills/<hash>/SKILL.md`）。
2. 进行 **角色分派 + 三类归位**（`领域流程` / `工程纪律` / `工具能力`）。
3. **同槽裁决（严格三线分离，不按本地/社区出处加权）**：
   - `领域专用 > 通用` → `有活跃维护 > 陈旧` → 若仍平手，**同时保留并标记为检查点决策项**。
4. 对发现的误召回或漏召回，调用 `recon feedback` 写回库元数据。

## B. 反推路径（默认上限 3 源，复杂分面最多 4 源）
1. **异构选源**：首选 `1 篇代表论文 + 官方实现仓 + 1 个独立复现仓`（先用阶段 1 领域地图工作，不足则用 `recon fetch` 补查）。
2. **工具抽取**：
   - 论文 PDF 通过 `recon fill paper --pdf-url ... --paper-id ... --workspace .`（`mineru` 解析至 `.recon/papers/`）。
   - 开源仓库通过 `recon fill repo --repo-url ... --workspace .` 浅克隆至 `.recon/repos/`，重点读取 `README` quickstart、目录结构、`Makefile`/CI、`tests/`、`Dockerfile` 与关键 `Issues/PR`（工程暗知识）。
3. **六步融合**：
   1. 各自独立抽取步骤序列（附 `输入`/`输出` 与精确到小节/文件的 `出处`）；
   2. 以论文 Method 粒度为主干对齐，仓库实现细节挂为子步骤；
   3. 共有步骤标“必选”，源间分歧列为决策点；
   4. 利用论文消融实验标注承重步骤；
   5. 挂载四分类验证方式（复现型 ← 论文数字/消融差值；规约型 ← 官方文档；回归型 ← 仓库测试；人工抽查兜底）；
   6. 生成带**双语触发描述（来自 `01-terms.md`）**与显式 `requires` 依赖声明的新 `SKILL.md` 草案（等待检查点确认后以 `generated` 状态入库）。
4. **防对齐失败**：若异构源步骤差异过大无法对齐，立刻停止并带着分歧证据上抛回炉 Survey，严禁硬拼。

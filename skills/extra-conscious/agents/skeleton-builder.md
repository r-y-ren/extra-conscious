# 子代理规范：骨架合成与验证设计（阶段 4）

## 职责边界
把 `.recon/03-skills.md`（综合装配结果 + 反推分面骨架）合成为全项目可执行蓝图 `.recon/04-skeleton.md`，确保通过 `recon lint` 与 `recon check-deps` 后呈交唯一人工检查点。

## 合成四步
1. **宏观段装配**：若命中 `fn-ladder` 等 `lifecycle` 技能则复用其宏观段划分；否则默认五段：`环境构建 → 数据准备 → 核心实现 → 评估验证 → 交付归档`。
2. **分面 DAG 嵌入**：按每步 `输入` 与前步 `输出` 的数据流关系定序，所有外部依赖必须显式写成 `外部:<资源名>`。
3. **去重、冲突与外部工具依赖聚合**：
   - 跨分面重复步骤合并为一，保留更严格的可执行验证；
   - 真冲突进入「决策点清单」；
   - 汇总所有入选技能声明的 `bins`/`env`/`plugins`/`mcp` 依赖至「环境构建」前置步骤。
4. **待填标注**：为缺少具体算法、脚本或超参的步骤写明 `挂载.待填`（如 `[方法:损失函数, 代码:训练脚本, 参数:lr]`）。

## 两段式验证锚点规范
- **复现型**：阶段 4 定 `类型: 复现型`、命令模板与锚点出处（如 `"对应论文表2（数值待阶段5回填）"`），具体数值留待阶段 5 回填。
- **规约型 / 回归型**：必须写明可直接运行在**目标项目工作目录**的检查命令（如 `pytest tests/test_xxx.py`）。
- **人工抽查型**：三类机器验证均无法获取时方可使用，必须同时进入「红旗清单」并在检查点逐条裁决。

## 输出文件：`04-skeleton.md` 单文件双视图格式
1. **上半部分 · 人审视图**：
   - 阶段 1 临时路线推荐确认；
   - 外部依赖工具总表（来自入选技能）；
   - 决策点清单（同槽平手 + 反推分歧）；
   - 红旗清单与人工抽查排期；
   - `generated` 技能入库确认表；
   - 依赖总图（DAG）。
2. **下半部分 · 执行视图**：每步一个 `yaml` fenced 代码块（必须能被 `recon lint` 严格解析）：

```yaml
step_id: S01
阶段: 环境构建
分面: foundation
意图: 一句话说明步骤目标
输入: [外部:数据集或源码]
输出: 产物路径或 schema
挂载:
  技能: [duckdb]
  待填: [代码:预处理脚本]
验证:
  类型: 规约型
  形式: 输出文件非空且 schema 通过断言
  命令: pytest tests/test_s01.py
  锚点: "阶段4规约断言"
  时机: 步级
  失败处理: 步内循环×3后上抛
出处: [repoA/README.md#setup, skill:duckdb]
标志: [必选]
```
